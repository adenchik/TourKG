# Техническое задание (ТЗ) на разработку веб-приложения для продажи туров по Кыргызстану

## 1. Общие сведения

**Название проекта:** (Рабочее название: *TourKG*)
**Цель:** Создание веб-приложения с функционалом PWA (Progressive Web App) для просмотра и покупки туристических туров.
**Тип приложения:** E-commerce / Booking platform.
**Целевая аудитория:** Туристы (местные и иностранные), желающие посетить достопримечательности Кыргызстана.

## 2. Стек технологий

* **Язык программирования:** Python 3.13+
* **Backend фреймворк:** Django 5.x
* **Шаблонизатор:** Jinja2 (интегрированный в Django) или Django Templates (на выбор разработчика, далее — Шаблоны).
* **База данных:** SQLite (для разработки и MVP).
* **Frontend стилизация:** TailwindCSS (подключение через CDN для dev или npm-сборка для prod).
* **Frontend логика:** Vanilla JavaScript (без React/Vue/Angular).
* **Контроль версий:** Git.
* **PWA:** Service Workers, Web App Manifest.

## 3. Роли пользователей

В системе предусмотрены две основные роли:

### 3.1. Гость (Пользователь)

* Не требует регистрации для просмотра.
* Видит список всех доступных туров.
* Может открыть детальную страницу тура.
* Может оформить заказ (покупку).

### 3.2. Администратор (Суперюзер)

* Имеет доступ в административную панель (Django Admin).
* Управляет контентом (CRUD операции для туров).
* Просматривает поступившие заявки/заказы.

## 4. Функциональные требования

### 4.1. Главная страница (Витрина)

* **Header:** Логотип, название, кнопка "Связаться" или ссылка на контакты.
* **Hero-секция:** Приветственное изображение (горы/Иссык-Куль), заголовок, краткое описание.
* **Список туров (Grid):** Карточки туров.
    * *Состав карточки:* Фото превью, Название тура, Дата, Цена, Краткое описание (обрезанное), Кнопка "Подробнее".
* **Footer:** Ссылки на соцсети, контакты, копирайт.

### 4.2. Страница детального просмотра тура

* Галерея изображений (слайдер или сетка).
* Полное название и локация.
* Подробное описание программы (таймлайн).
* Условия (что включено/не включено).
* Дата и время сбора.
* Максимальное кол-во человека на туре (1/4).
* Цена билета за 1 человека.
* **Sticky-блок (или кнопка внизу на мобильных):** "Купить тур". При нажатии открывает модальное окно или переводит на
  форму оплаты.

### 4.3. Оформление заказа (Покупка)

* Форма сбора данных:
    * Имя и Фамилия.
    * Номер телефона (с валидацией маски).
    * Email (для отправки билета).
* **Интеграция оплаты:**
    * *(Эквайринг):* Интеграция с платежным шлюзом (Freedom Pay, PayBox, Stripe, Finik) — перенаправление на страницу
      оплаты банка.

### 4.4. Административная панель (Django Admin)

* **Раздел "Туры":**
    * Добавление/Редактирование/Удаление.
    * Поля: Название, Слаг (URL), Описание, Цена, Дата, Локация, Главное фото, Статус (Активен/Архив).
* **Раздел "Заказы":**
    * Просмотр списка заказов.
    * Фильтрация по статусу оплаты.
    * Возможность менять статус вручную.

### 4.5. PWA Функционал

* Приложение должно предлагать установку на рабочий стол ("Add to Home Screen").
* Наличие `manifest.json` (иконки, название, цвета темы).
* Наличие `service-worker.js`: кэширование статики (CSS, JS, логотип) и страницы "Оффлайн" при отсутствии интернета.

## 5. Структура Базы Данных (Примерная схема)

### Модель `Tour` (Туры)

| Поле          | Тип           | Описание                            |
|:--------------|:--------------|:------------------------------------|
| `id`          | AutoField     | PK                                  |
| `title`       | CharField     | Название тура                       |
| `slug`        | SlugField     | ЧПУ ссылка                          |
| `description` | TextField     | Полное описание (HTML или MD)       |
| `image`       | ImageField    | Обложка тура                        |
| `price`       | DecimalField  | Цена за 1 человека                  |
| `count_max`   | IntegerField  | Максимальное кол-во человек на туре |
| `date_start`  | DateTimeField | Дата начала                         |
| `location`    | CharField     | Место проведения                    |
| `is_active`   | BooleanField  | Отображать на сайте?                |

### Модель `Order` (Заказы)

| Поле            | Тип                  | Описание               |
|:----------------|:---------------------|:-----------------------|
| `id`            | AutoField            | PK                     |
| `tour`          | ForeignKey           | Ссылка на тур          |
| `customer_name` | CharField            | Имя клиента            |
| `phone`         | CharField            | Телефон                |
| `email`         | EmailField           | Email                  |
| `total_price`   | DecimalField         | Итоговая сумма         |
| `status`        | CharField            | (new, paid, cancelled) |
| `created_at`    | DateTimeField        | Дата создания заказа   |

## 6. Требования к интерфейсу (UI/UX)

* **Дизайн:** Минимализм, акцент на фотографии природы Кыргызстана.
* **Цветовая гамма:** Использовать Tailwind colors. Основные: `emerald-600` (зелень/горы), `sky-500` (небо/озера),
  `slate-800` (текст).
* **Адаптивность:** Mobile-First подход. Сайт должен идеально выглядеть на смартфонах (основной кейс использования PWA).
* **Шрифты:** Sans-serif (например, Inter или Roboto).

## 7. Этапы разработки

1. **Настройка окружения:**
    * Инициализация Django проекта.
    * Настройка TailwindCSS (через CLI input.css -> output.css).
    * Настройка Jinja2 (опционально) или настройка папок templates.
2. **Бэкенд (База):**
    * Создание моделей `Tour` и `Order`.
    * Настройка админки (вывод нужных полей, поиск).
3. **Фронтенд (Верстка):**
    * Создание базового шаблона (`base.html`) с шапкой и подвалом.
    * Верстка главной страницы (список).
    * Верстка детальной страницы.
    * Верстка формы заказа.
4. **Бизнес-логика:**
    * Реализация views для отображения туров.
    * Обработка POST-запроса формы заказа.
    * Валидация данных.
5. **PWA внедрение:**
    * Генерация иконок.
    * Настройка манифеста.
    * Написание Service Worker для оффлайн-страницы.
6. **Тестирование и деплой:**
    * Проверка пути пользователя (выбор -> покупка).
    * Загрузка на сервер (VPS/PythonAnywhere).

## 8. Нефункциональные требования

* Скорость загрузки главной страницы (LCP) < 2.5 сек.
* Безопасность: Защита от CSRF (встроено в Django), валидация вводимых данных.
* Код должен быть чистым, соблюдать PEP8.
* SQLite файл должен быть исключен из Git, если планируется деплой, но для локальной разработки `db.sqlite3` добавляется
  в `.gitignore`.
